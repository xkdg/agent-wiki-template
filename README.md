# Agent Wiki Template

Шаблон инфраструктуры документации для AI-агента (Claude Code / Cursor / любой LLM-агент с file-tools) в кодовом проекте.

Идея: дать агенту не «свободу импровизации в большом контексте», а **узкий протокол** — что читать перед задачей, какой жанр документа для какого типа знания, что обновлять после задачи. Каждый артефакт играет одну роль, не пересекается с другими, имеет понятное время жизни.

---

## Что внутри

```
agent-wiki-template/
├── README.md                       ← этот файл
├── CLAUDE.md                       ← универсальный протокол агента (копируется в корень нового репо ~as-is)
└── wiki/
    ├── INDEX.md                    ← точка входа: «что за проект», карта wiki, роутинг, чек-листы
    ├── context/
    │   ├── QUICK_REF.md           ← cheat sheet, читается на каждой задаче
    │   ├── PRODUCT.md             ← бизнес-описание: процессы, интеграции, данные (mermaid-схемы)
    │   ├── CONVENTIONS.md         ← правила «как надо / как не надо» (C-NN), с прецедентом
    │   └── POSTMORTEMS.md         ← post-mortem инцидентов (сырьё, амортизируется)
    ├── adr/
    │   └── _TEMPLATE.md           ← шаблон ADR (00NN-<тема>.md)
    └── todo/
        ├── _TEMPLATE.md           ← шаблон ТЗ
        ├── BACKLOG.md             ← планируемое
        └── TECH_DEBT.md           ← осознанные долги (TD-NN)
```

## Жанровая граница (важно)

Каждый артефакт = одна роль. Не пересекаются, не дублируются.

| Артефакт | Жанр | Что попадает | Время жизни |
|---|---|---|---|
| **CLAUDE.md** | Протокол агента | Что читать до задачи и проверять после, подход к работе, субагенты, когда заводить ТЗ | Постоянно |
| **INDEX.md** | Точка входа в проект | Что за проект, карта wiki «куда идти за чем», чек-лист значимости, матрица документации | Долго, обновляется по мере роста |
| **QUICK_REF.md** | Cheat sheet | Границы-инварианты + state machine, формулы, пороги — то, что нужно на каждой задаче | Долго, апдейтится при изменении инвариантов |
| **PRODUCT.md** | Бизнес-описание (BABOK RADD-модели) | Продукт, акторы (C4 L1), процессы (flowchart), интеграции (sequence), данные (ER) — схема первична | Долго |
| **CONVENTIONS.md** | Правила реализации | «Как надо / как не надо» с прецедентом и first cause (`C-NN`) | Долго |
| **POSTMORTEMS.md** | Post-mortem | Лог инцидента: симптом → диагностика → root cause → фикс. **Сырьё**, амортизируется | Запись удаляется, когда урок переехал в CONVENTIONS / ADR |
| **ADR** | Прескриптивное решение | Контекст → решение → альтернативы → последствия. Принимается **до или вместе** с реализацией | Постоянно. Заменяется только новым ADR через `Supersedes` |
| **TECH_DEBT.md** | Состояние системы | Сознательные компромиссы, риски, статусы accepted/planned/partial (`TD-NN`) | Долго |
| **BACKLOG.md** | Намерения | Что планируем сделать. `[x]` отметка прямо в файле, не плодим архивы | Долго |
| **todo/<task>.md** | ТЗ | Декомпозиция конкретной задачи. После `done` — удаляется, если уникальной ценности не осталось | Короткое (живёт одну задачу) |

**Принцип амортизации:** свежий урок живёт в `POSTMORTEMS.md`. Когда он переехал в долгоживущий артефакт (ADR / CONVENTIONS) — исходная запись **удаляется**, не дублируется.

**Принцип единственного источника истины:** каждый факт живёт в одном месте + cross-refs в смежных. Дубль текста = долг.

**Принцип «отметка на месте, не архив»:** выполненная задача из BACKLOG / любого ТЗ отмечается `[x]` в исходном файле. Никаких `COMPLETED_*.md` архивов.

## Как использовать в новом проекте

1. Скопировать содержимое `agent-wiki-template/` в корень нового репо:
   ```
   cp -r agent-wiki-template/CLAUDE.md  <new-project>/
   cp -r agent-wiki-template/wiki       <new-project>/
   ```
   (содержимое `agent-wiki-template/README.md` копировать не нужно — это про сам шаблон)

2. **CLAUDE.md** — оставить почти как есть. Это универсальный протокол агента; конкретику смотрит в `wiki/INDEX.md`.

3. **wiki/INDEX.md** — заполнить под проект:
   - Что за проект (2–4 предложения) + текущий фокус
   - «Карта wiki» — проектный роутинг по подсистемам
   - Чек-лист значимости и матрица документации — привязать к вашим файлам

4. **wiki/context/QUICK_REF.md** — заполнить: `§Границы` (инварианты, нарушение = сначала ADR) + факты: state machine, пороги/формулы, команды запуска. Только то, что нужно на каждой задаче. Не дублировать архитектуру.

5. **wiki/context/PRODUCT.md** — заполнить бизнес-описание: контур акторов (C4 L1), процессы flowchart'ами, интеграции (таблица + sequence), данные (ER + словарь сущностей).

6. **CONVENTIONS.md / POSTMORTEMS.md / TECH_DEBT.md / BACKLOG.md** — стартуют почти пустыми. Наполняются по мере работы.

7. **adr/_TEMPLATE.md / todo/_TEMPLATE.md** — шаблоны на копирование, удалять не нужно.

## Идеология

Протокол агента (`CLAUDE.md`) стоит на принципах «думать до кода · минимум кода · хирургические правки · проверяемые критерии», а wiki замыкает цикл: агент знает, **что именно** читать перед задачей и **что именно** обновлять после. Нумерация и форматы записей — в шапках самих файлов; сквозные принципы документирования — в `INDEX.md §После задачи`.
