## Проект

*2–4 предложения: что делает система, для кого, на каком масштабе; одной строкой — пайплайн/структура. Фактическое описание без маркетинга.*

*Пример: Автоматическое обогащение реестра юрлиц tech-стеком и контактами. Вход — список организаций, выход — Parquet с верифицированным сайтом, стеком, контактами. Пайплайн: `search` → `crawl` → `llm-analyze` → `export`; координация через PostgreSQL (state machine), без прямых вызовов между сервисами.*

**Текущий фокус:** *1–2 предложения, что сейчас в работе; обновлять при смене фокуса. Пример: миграция Stage 4 на новую библиотеку; открытые задачи — в `todo/BACKLOG.md`.*

## После задачи — матрица документации

*Единственное место, отвечающее на «куда писать». Правая колонка — с привязкой к файлам этого проекта.*

| Что я сделал | Куда пишу |
|---|---|
| Bug fix с нетривиальной диагностикой (>30 мин расследования или неочевидный симптом) | `context/POSTMORTEMS.md` — новая запись `## YYYY-MM-DD — <сервис>: <тема>` |
| Найден переиспользуемый приём или антипаттерн — правило с прецедентом | + `context/CONVENTIONS.md` (новая запись `C-NN`, грани «как надо» / «как не надо») |
| Архитектурное решение — выбор из явных вариантов, влияет на >1 компонент или схему данных | `adr/00NN-<тема>.md`: контекст → решение → альтернативы → последствия |
| Изменён инвариант, описанный в ADR | обновить тот ADR (или новый со `Supersedes ADR-XXXX`) |
| Изменена state machine / формула / пороги | `context/QUICK_REF.md` |
| Изменён бизнес-процесс / интеграция / схема данных | `context/PRODUCT.md` (соответствующая секция и её диаграмма) |
| Сознательный «костыль на потом» | `todo/TECH_DEBT.md` (новая запись `TD-NN`) |
| Завершена задача из любого ТЗ-документа (BACKLOG, DEV_SPEC, PLAN и т.п.) | отметить `[x]` **прямо в исходном файле**, не плодить отдельный архив (принцип полностью — в шапке `BACKLOG.md`) |
| Новая задача / идея, не делаем сейчас | `todo/BACKLOG.md` |

**Принципы документирования:**
- **Амортизация.** `POSTMORTEMS.md` — сырьё: когда урок переехал в ADR / `CONVENTIONS`, исходную запись удалить (она стала дублем).
- **Единственный источник истины.** Каждый факт живёт в одном месте, в смежных — cross-refs. Дубль текста = долг: при правке одной копии остальные молча устаревают.
- **Cross-references.** В каждой записи — строка `См. также:` со связанными ID («C-12, ADR-0003, TD-02»).
- **Нумерация.** Все ID (`ADR-00NN`, `C-NN`, `TD-NN`) sequential и **никогда не переиспользуются** (запись удалена — номер не возвращается); полный ID в заголовке записи. Детали формата — в шапках самих файлов.
- **Ссылки на смертное.** ТЗ-файлы и записи POSTMORTEMS умирают — из долгоживущих артефактов (ADR / CONVENTIONS / PRODUCT) на них не ссылаться; нужную деталь переносить в сам документ.
