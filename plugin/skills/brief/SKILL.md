# Бриф фичи

Цель — понимание, которое владелец узнаёт и может поправить, записанное проверяемо. **До одобрения — только чтение и разведка:** ни кода, ни зависимостей, ни скаффолдинга.

Паттерны — из obra/superpowers `brainstorming` (классификация, гейт), github/spec-kit `clarify` (вопросы по одному с рекомендацией, карта покрытия), ECC `intent-driven-development` (сначала контекст, бизнес — только от владельца, наблюдаемые критерии).

## 0. Классифицировать — вслух, до первого вопроса

| Класс | Признак | Выход |
|---|---|---|
| **Проба** | «можно ли / получится ли»; результат — ответ, не код | 2–3 предложения, что и как проверим → «ок» → вывод рекомендацией; построенное — одноразовое |
| **Ограниченная** | правка потока, который уже есть в репо и читается в коде | короткий дизайн в чате → явное «да» → реализация; ТЗ нет |
| **Крупная** | новая подсистема; меняет контракт, данные, инвариант; больше пары часов; нечёткий скоуп | полный путь → ТЗ-файл |

Сомнение — брать тяжелее. Скрытая сложность по ходу повышает класс (остановиться, сказать); понижения нет.

## 1. Контекст до вопросов

- ADR и `C-NN` задетых подсистем — по роутингу `INDEX`. Код — поручить `scout`: точки входа, похожие реализации, инварианты, что из кода не выводится.
- **Технические факты — из кода, не спрашивать.**
- **Бизнес-ограничения — только от владельца** или из названного им документа: правила предметной области, потребители, приоритеты, сроки, SLA, юридические и денежные рамки. Из кода не восстанавливать; до подтверждения — помеченное допущение.

## 2. Вернуть понимание

Цель одним предложением, потребитель результата, вход и выход, как поймём, что получилось. Раздельно «вы сказали» и «я предполагаю». Дождаться поправки; что уже есть в запросе — отразить, а не переспрашивать.

## 3. Вопросы — по одному

Молча пройти карту, спрашивать только по неясному — и только если ответ меняет скоуп, данные, критерии или риск:

| Область | Что выяснить |
|---|---|
| Цель и потребитель | кто использует результат и что с ним делает |
| Скоуп | что в задаче; что **вне** — особенно соблазн «заодно» |
| Данные | сущности, уникальность, пропуски, объёмы, откуда и куда |
| Инварианты | какие пункты `QUICK_REF §Границы` задеты |
| Отказы | сбой источника, частичные данные, повторный прогон |
| Нефункциональное | время, объём, стоимость внешних вызовов |
| Контракты | API, CLI, форматы; кто потребляет, что сломается |
| Необратимое | миграции, массовые `UPDATE`, деплой, удаление |
| Приёмка | как владелец сам убедится, что готово |

- Один вопрос за сообщение; очередь — по «влияние × неопределённость»; за круг до 5, следующий — только если остались блокирующие.
- Полное вопросительное предложение, под ним — «почему важно» и **рекомендация с обоснованием**. 2–4 варианта — через `AskUserQuestion`, если есть, иначе таблицей с буквами.
- «На твоё усмотрение» — принять рекомендацию, записать допущением. Не спрашивать читаемое из кода и стилистику.

## 4. Подходы — только для крупной

2–3 варианта с компромиссами и рекомендацией. Решение с реалистичными альтернативами и влиянием шире реализации — кандидат в ADR (`RULES.md §Когда предлагать ADR`): назвать, не заводить.

## 5. Критерии приёмки

Каждый наблюдаем: исходное состояние → действие → результат; чего не должно случиться, если важно; чем проверяется (тест, запрос, скрипт, ручная проверка владельцем); где безопасно проверять, если трогает данные или прод. «Корректно», «быстро», «надёжно», «удобно» без числа или признака — недопустимы; числа нет — это вопрос владельцу, а не цифра на глаз.

## 6. Декомпозиция и фиксация

- По границам `wiki/todo/_TEMPLATE.md`; больше одного ТЗ — серия с «Зависит от» или сначала ADR. Шаг плана — одно действие с контрольной точкой.
- **Крупная** — `wiki/todo/<short-kebab-name>.md`, статус `draft` (создание одобрения не требует, реализация — требует). **Ограниченная** — дизайн в чате: подход, задетые файлы, как проверим.
- Самопроверка: нет заглушек и «TBD» без того, кто ответит; нет противоречий; каждый критерий проверяем; «НЕ входит» не пусто; допущения помечены.
- Показать и ждать явного «да». Одобрение идеи не одобряет артефакты, которых ещё нет.

## Красные флаги

- «Очевидно, бриф не нужен» — ограниченной хватит двух предложений, но одобрение всё равно до кода.
- «Назову ограниченной, чтобы не писать ТЗ» — это и есть сомнение: брать тяжелее.
- «Начну, пока владелец читает» — гейт — одобрение, а не длина дизайна.
- «Бизнес-правило видно из кода» — код показывает как есть, а не как нужно.
- «Задам все вопросы списком» — на список из десяти отвечают на три.
