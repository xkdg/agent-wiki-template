# Post-mortems — лог инцидентов

> Дескриптивный лог: симптом → диагностика → root cause → фикс → урок. **Сырьё, амортизируется:**
> когда урок переехал в `CONVENTIONS.md` / новый ADR — запись удалить
> (принцип — `wiki/INDEX.md §После задачи`). Остаются только записи, чей урок ещё не переехал,
> и частные случаи без обобщения.
>
> **Формат записи:** `## YYYY-MM-DD — <сервис>: <короткая суть>`. Дата — день фиксации post-mortem
> (не день инцидента, если расходятся); `<сервис>` — имя сервиса или `shared`. Без ID.

---

## Шаблон записи (удалить после первой реальной)

## YYYY-MM-DD — <сервис>: <короткая суть инцидента>

**Триггер:** *как обнаружен — smoke-тест, прод-алерт, ручной запуск с флагом, …*

**Симптом:** *что наблюдалось снаружи: ошибки, метрики, поведение. Без интерпретации.*

**Диагностика:** *как локализовали причину; минимальный repro, если есть.*

**Root cause:** *что именно сломалось и почему — цепочка причина → следствие, а не «сломался X, починили Y».*

**Фикс:** *что изменили: файл, функция, суть правки (не diff — суть; короткий до/после, если уместен).*

**Урок → амортизация:** *что и куда переехало: `C-NN` / новый ADR — или «частный случай, без обобщения» с обоснованием. Условие, при котором запись можно удалить.*

**Связано:** *файлы кода, `ADR-00NN`, `C-NN`*
