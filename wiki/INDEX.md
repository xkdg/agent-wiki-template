## Проект

*2–4 предложения: что делает система, для кого, что на входе и что на выходе; одной строкой — пайплайн или структура. Фактическое описание без маркетинга. Дальше — ключевые архитектурные развилки со ссылками на ADR: то, чего агент не выведет из кода за разумное время.*

*Здесь же — где искать недоделанное и где искать сделанное, чтобы вторая копия статуса не заводилась: планы — `todo/BACKLOG.md`, сделанное — ADR и git log.*

## Куда идти за чем

| Нужно узнать | Канонический источник |
|---|---|
| Что за проект, команды, как запустить | `README.md` |
| Границы, state machine, формулы, пороги, контракты данных | `context/QUICK_REF.md` |
| Продукт, процессы, интеграции, данные — схемами | `context/PRODUCT.md` |
| Правила реализации с прецедентами | `context/CONVENTIONS.md` (`C-NN`) |
| Почему принято архитектурное решение | `adr/` — тему называет имя файла |
| Что делаем дальше | `todo/BACKLOG.md` |
| ТЗ живых задач | `todo/<name>.md` (шаблон `_TEMPLATE.md`, когда заводить — `CLAUDE.md §ТЗ-файл`) |

**Таблица описывает жанры, а не файлы: новый документ в существующей категории её не меняет.** Каталога ADR здесь нет намеренно — действующие решения это ровно то, что лежит в `adr/`. Списанный ADR удаляется вместе со своим номером: номер не переиспользуется, история живёт в git log. Следующий номер — `0001`, форма — `adr/_TEMPLATE.md`.

## Карта кода — роль читается из пути

*Опционально, но окупается быстро: дерево пакета с однострочным назначением каждой директории. Ценность не в списке файлов — его даёт файловая система, — а в том, что из пути читается роль модуля и направление зависимостей.*

```
<пакет>/
├── <точки входа>       ← пути команд неизменны
├── core/               ← основание: конфиг, БД, события — не знает ни о ком
├── <sources|adapters>/ ← внешние данные
└── <domain>/           ← прикладная логика
```

*Если направление импортов важно — проверять его тестом, а не обещанием (обход AST по всему пакету), и назвать этот тест здесь. Тогда модуль, положенный в корень «пока непонятно куда», роняет тест, а не остаётся жить.*

*Ниже — отображение понятий на файлы, чего файловая система не даёт, и потому поддерживается руками. Новый документ таблицу не меняет: строка правится, только когда появилась подсистема или сменился канонический источник по строке.*

| Подсистема | Куда идти |
|---|---|
| *например, скоринг* | *`adr/0007-….md`, `QUICK_REF §Формулы`, `<путь к коду>`* |
| *например, анти-бан* | *`C-12`, `<путь к коду>`* |

## Когда предлагать ADR

*Предложение, а не создание: ADR заводится после явного одобрения (`CLAUDE.md §Протокол агента`). Объём правки критерием не является — однострочная правка бывает значимой, а рефакторинг на тысячу строк не бывает.*

**Все четыре условия сразу:**
1. принято долговечное решение, а не просто выполнена задача;
2. есть минимум две реалистичные альтернативы, и отвергнутая отсечена названным критерием;
3. решение влияет шире собственной реализации;
4. мотивация неочевидна из кода, тестов и конфигурации.

**И задета хотя бы одна область.** *Левая колонка переносится как есть, правая заполняется под проект: неприменимую область пометить `—`, свою — дописать.*

| Область | Признаки в этом проекте |
|---|---|
| **State machine** | *финальные статусы, флаги и переходы; где они заданы* |
| **Схема БД** | *механизм миграций, ключевые таблицы* |
| **Контракт API / CLI** | *модули точек входа, где описаны флаги и эндпоинты* |
| **Протокол между компонентами** | *типы и события, которыми компоненты обмениваются* |
| **Конфиги / пороги / формулы** | *где живут пороги: таймауты, TTL, размеры батчей* |
| **Инвариант из `QUICK_REF §Границы`** | *сколько пунктов; менять — сначала ADR* |
| **Cross-cutting** | *обработка ошибок, retry, деградация, наблюдаемость* |
| **Стоимость** | *если есть оплачиваемые внешние вызовы — их лимиты и цены* |

**ADR не заводится** для обычного bug fix, локального рефакторинга, имени файла или функции, поля по существующему паттерну, реализации уже принятого решения, восстановления прежнего поведения, настройки библиотеки внутри выбранного стека и решения, целиком читаемого из публичного контракта и тестов.

## После задачи — `documentation_action`

**Умолчание — `none`.** Ниже маршруты «что куда»; чего в списке нет, то по умолчанию `none`. Состояния и различие «неверное чинится, новое называется» — `CLAUDE.md §Протокол агента`.

*Строки без курсива переносятся как есть; курсивом — то, что заполняется под проект. Список ведётся коротким: маршрут заводится, когда расхождение уже случалось, а не на всякий случай.*

| Что произошло | Действие |
|---|---|
| Изменено число, статус, формула или контракт, описанные в `QUICK_REF` | `update_existing`: `context/QUICK_REF.md` |
| Изменён процесс, интеграция или схема данных, описанные в `PRODUCT` | `update_existing`: `context/PRODUCT.md` — секция и её диаграмма |
| Изменён контракт команды или эндпоинта из `README §Команды` | `update_existing`: `README.md` |
| Появилась подсистема или сменился канонический источник по строке | `update_existing`: таблица подсистем в этом файле |
| Изменён инвариант из `QUICK_REF §Границы` | **оба сразу:** `update_existing` `QUICK_REF` — иначе документ, читаемый перед каждой задачей, остаётся с ложным инвариантом; и `propose_new`: ADR со строкой `Supersedes` |
| Прошёл gate `§Когда предлагать ADR` | `propose_new`: ADR |
| Приём или дефект встретился в двух независимых местах либо однажды дорого | `propose_new`: `C-NN` — при остальных условиях шапки `CONVENTIONS.md`: шире одного файла, названное последствие, не держится тестом или типом |
| Сознательный костыль остаётся жить | назвать в финале; **границу, которую он держит, — `update_existing`: `QUICK_REF`** |
| Попутная находка, идея или отложенная проблема | назвать в финале. `BACKLOG` и вики не трогать |
| Задача велась по ТЗ | `[x]` и статус в самом файле; `done` + подтверждённая приёмка → амортизация и удаление |
| *Изменён артефакт, приёмка которого требует прогона (промпт, модель, эвал-набор)* | *в вики — `none`, но без прогона не принимается; версии уезжают в трейс* |
| *Сознательное отступление от скоупа исходного ТЗ заказчика* | *`propose_new`: ADR — что и почему изменено* |

Расхождение, замеченное при чтении, — тоже `update_existing`, независимо от того, чем оно вызвано: документ, который врёт, дороже документа, которого нет.

## Принципы документирования

- **Амортизация.** Документ живёт, пока его содержимое не переехало в долговечное место. Переехало — исходный удаляется: две копии расходятся, и вторая начинает врать.
- **Единственный источник истины.** Каждый факт живёт в одном месте; смежный документ на него ссылается, а не пересказывает.
- **Ссылки — по необходимости.** Ссылка ставится в тексте там, где без неё теряется контекст. Отдельной секции связей и обратных ссылок нет: граф, поддерживаемый руками, устаревает первым, а отсутствие ссылки дефектом документа не является.
- **Правило, которое можно проверить машиной, проверяется машиной.** Тест, тип, схема или линтер вместо записи в вики; текстовое правило — когда автоматизировать нечем. Запись тогда ссылается на механизм, а не пересказывает его.
- **Реестра долгов нет.** Найденная проблема либо чинится на месте, либо называется в финале; пункт `todo/BACKLOG.md` заводится по одобрению. Отдельного списка «с чем живём» не бывает — архив, который никто не разгребает, начинает врать. Принятый компромисс описывается в «Последствиях» того ADR, который его породил, вместе с ценой.
- **Нумерация.** `ADR-00NN` и `C-NN` — sequential, **никогда не переиспользуются**.
- **Ссылки на смертное.** ТЗ-файлы умирают — из ADR, `CONVENTIONS`, `PRODUCT` и `QUICK_REF` на них не ссылаться. Исключение — помеченные постоянными.
