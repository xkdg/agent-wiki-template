# Обновить ядро кита в проекте

Процедура целиком — `kit/INSTALL.md §sync` и `§Конфликты` в репозитории кита. Ничего не коммитить без согласия владельца.

## 1. Получить свежий кит

```bash
KIT="${CLAUDE_PLUGIN_DATA}/kit"
if [ -d "$KIT/.git" ]; then git -C "$KIT" fetch -q origin && git -C "$KIT" checkout -q --detach origin/main; else git clone -q https://github.com/xkdg/agent-wiki-template "$KIT"; fi
```

Переменная не подставилась — временный каталог. Клон полный: sync читает прошлую версию из истории.

## 2. Посмотреть, потом применить

```bash
python "$KIT/kit/kit.py" sync --project "<корень проекта>" --dry-run
python "$KIT/kit/kit.py" sync --project "<корень проекта>"
```

Нет `python` — `python3`. Только вопрос «какая версия / что изменилось» — `status` вместо `sync` и `git -C "$KIT" log` по `CHANGELOG.md`.

## 3. Конфликты — решает владелец

Конфликт = файл ядра правили в проекте. Для каждого показать оба diff из отчёта и предложить один из трёх исходов (`kit/INSTALL.md §Конфликты`):
- проектное попало в ядро → перенести в `wiki/context/QUICK_REF.md` (или личное — в `~/.claude/CLAUDE.md`), взять версию кита;
- общее улучшение → оставить и предложить в кит через `/agent-wiki:upstream`;
- устаревшая правка → взять версию кита.

После разрешения всех — команда `stamp`, которую напечатал sync.

## 4. Отчёт

Версия «было → стало», обновлённые файлы, конфликты и как разрешены, что из `CHANGELOG.md` касается этого проекта (особенно записи с инструкцией миграции).
