# Agent Wiki Template

Кит инфраструктуры документации для AI-агента (Claude Code / Cursor / любой LLM-агент с file-tools) в кодовом проекте: протокол агента, вики проекта, роли субагентов и бриф фичи.

Идея: дать агенту не «свободу импровизации в большом контексте», а **узкий протокол** — что читать перед задачей, какой жанр документа для какого типа знания, что делать с документацией после задачи. Каждый артефакт играет одну роль, не пересекается с другими, имеет понятное время жизни.

Кит развёртывается в новый проект одной командой с любого устройства, обновляется в уже развёрнутых проектах и принимает улучшения обратно из живых проектов.

---

## Установка — один раз на аккаунт

Кит — две части:

| Часть | Что | Где живёт | Как обновляется |
|---|---|---|---|
| **Плагин `agent-wiki`** | роли субагентов, скиллы `brief`, `init`, `sync`, `upstream` | ставится на аккаунт или машину | сам, по каждому коммиту в этот репозиторий |
| **Файлы проекта** | `CLAUDE.md` и `wiki/` | в репозитории каждого проекта | `/agent-wiki:sync` в проекте |

**Плагин — через claude.ai** (рекомендуется): Customize → Plugins → добавить маркетплейс из GitHub `xkdg/agent-wiki-template` → установить `agent-wiki`. Плагин, установленный на аккаунт, подтягивается в Claude Code на всех машинах и в облачные сессии, автообновление у маркетплейсов, добавленных с claude.ai, включено по умолчанию. В обычном чате claude.ai из плагина работают только скиллы; роли — в Claude Code и Cowork.

**Или только на эту машину — в Claude Code:**

```
/plugin marketplace add xkdg/agent-wiki-template
/plugin install agent-wiki@agent-wiki-template
```

Автообновление сторонних маркетплейсов здесь по умолчанию выключено — включить в `/plugin` → Marketplaces → `agent-wiki-template` → Enable auto-update.

Личные привычки, общие для всех проектов (как давать команды, язык ответов), — не в кит, а в `~/.claude/CLAUDE.md`.

## Работа

| Задача | Команда в Claude Code | Без плагина — сказать любому агенту |
|---|---|---|
| Новый проект | `/agent-wiki:init` | «Разверни xkdg/agent-wiki-template в этом проекте» — агент клонирует кит и следует `kit/INSTALL.md` |
| Обновить ядро в проекте | `/agent-wiki:sync` | «Обнови кит agent-wiki-template в этом проекте» |
| Новая фича, нечёткая задача | `/agent-wiki:brief` или просто «хочу добавить…» | шаги брифа — `plugin/skills/brief/SKILL.md` |
| Улучшение для всех проектов | `/agent-wiki:upstream` | «Предложи это в кит agent-wiki-template» |

С телефона: создать репозиторий в GitHub, открыть по нему облачную сессию Claude Code и сказать «разверни шаблон».

## Что внутри

```
agent-wiki-template/
├── template/                   ← что попадает в проект (состав — kit/MANIFEST)
│   ├── CLAUDE.md               ← ядро: протокол агента; импортирует INDEX, RULES, QUICK_REF
│   └── wiki/
│       ├── RULES.md            ← ядро: когда ADR / C-NN / скилл, маршруты после задачи, принципы
│       ├── INDEX.md            ← заготовка: что за проект, куда идти за чем, карта кода, области ADR
│       ├── context/
│       │   ├── QUICK_REF.md    ← заготовка: инварианты и факты на каждую задачу, договорённости проекта
│       │   ├── PRODUCT.md      ← заготовка: бизнес-описание схемами
│       │   └── CONVENTIONS.md  ← заготовка: правила реализации с прецедентом (C-NN)
│       ├── adr/_TEMPLATE.md    ← ядро: шаблон ADR
│       └── todo/
│           ├── _TEMPLATE.md    ← ядро: шаблон ТЗ
│           └── BACKLOG.md      ← заготовка: намерения
├── plugin/                     ← плагин agent-wiki
│   ├── agents/                 ← роли: scout, implementer, reviewer, verifier, investigator, doc-auditor
│   └── skills/                 ← brief, init, sync, upstream
├── kit/
│   ├── MANIFEST                ← какие файлы ядро (sync обновляет), какие заготовки (только init)
│   ├── kit.py                  ← init / sync / status / take / stamp — Python 3.8+, stdlib и git
│   ├── INSTALL.md              ← процедуры для агента: init, sync, конфликты, миграция, upstream
│   └── VERSION
├── .claude-plugin/marketplace.json
└── CHANGELOG.md
```

**Ядро** одинаково во всех проектах и в проекте не правится: улучшение уходит в кит через `upstream` и возвращается во все проекты через `sync`. **Заготовки** создаются один раз и дальше принадлежат проекту. Версия кита в проекте — `wiki/.kit-version`.

## Жанровая граница (важно)

Каждый артефакт = одна роль. Не пересекаются, не дублируются.

| Артефакт | Жанр | Что попадает | Время жизни |
|---|---|---|---|
| **CLAUDE.md** | Протокол агента | Что читать до задачи, четыре состояния `documentation_action` после, подход к работе, бриф, роли субагентов, когда заводить ТЗ | Постоянно, ядро кита |
| **RULES.md** | Правила документации | Гейты ADR и скилла, общие маршруты `documentation_action`, принципы документирования | Постоянно, ядро кита |
| **INDEX.md** | Точка входа в проект | Что за проект, куда идти за чем, карта кода, области ADR, проектные маршруты | Долго, обновляется по мере роста |
| **QUICK_REF.md** | Cheat sheet | Границы-инварианты + state machine, формулы, пороги, контракты данных — то, что нужно на каждой задаче | Долго, апдейтится при изменении инвариантов |
| **PRODUCT.md** | Бизнес-описание (BABOK RADD-модели) | Продукт, акторы (C4 L1), процессы (flowchart), интеграции (sequence), данные (ER) — схема первична | Долго |
| **CONVENTIONS.md** | Правила реализации | Правило + прецедент, из которого оно выведено (`C-NN`) | Долго |
| **ADR** | Прескриптивное решение | Контекст → решение → альтернативы → последствия. Принимается **до или вместе** с реализацией | Постоянно. Заменяется новым ADR через `Supersedes`; списывается вместе со своим номером |
| **BACKLOG.md** | Намерения | Что планируем сделать и по какому признаку это будет сделано | Долго |
| **todo/<task>.md** | ТЗ | Декомпозиция конкретной задачи, обычно — результат брифа. После `done` — амортизируется и удаляется | Короткое (живёт одну задачу) |
| **Скилл** `.claude/skills/` | Повторяемый процесс | Последовательность шагов и ловушки регулярного процесса этого проекта | Пока процесс жив |

**Принцип амортизации:** документ живёт, пока его содержимое не переехало в долговечное место. Переехало — исходный удаляется: две копии расходятся, и вторая начинает врать.

**Принцип единственного источника истины:** каждый факт живёт в одном месте; смежный документ на него ссылается, а не пересказывает. Дубль текста = долг.

**Реестра долгов нет.** Найденная проблема либо чинится на месте, либо называется в финале ответа; пункт бэклога заводится по одобрению. Отдельного списка «с чем живём» не бывает — архив, который никто не разгребает, начинает врать. Принятый компромисс описывается в «Последствиях» того ADR, который его породил, вместе с ценой.

**Правило, которое можно проверить машиной, проверяется машиной.** Тест, тип, схема или линтер вместо записи в вики; текстовое правило — когда автоматизировать нечем, и тогда оно ссылается на механизм, а не пересказывает его.

## Ядро протокола: `documentation_action`

Главное, чем этот шаблон отличается от «просто набора md-файлов»: после задачи агент **не обновляет документацию по умолчанию**. Умолчание — `none`, и обычная задача документацию не меняет. Всего состояний четыре:

| Состояние | Когда |
|---|---|
| `none` | умолчание |
| `update_existing` | документ утверждает то, что стало неверным. Правка точечная, на месте, нового жанра не заводит |
| `propose_new` | есть основание для нового долгоживущего артефакта: агент называет его в финале — тип, тема, основание, рекомендация. **Не создаёт** |
| `create_approved` | владелец продукта попросил или одобрил предложение |

**Различие, на котором всё держится: неверное утверждение чинится, новое знание называется.** Без явного одобрения не заводятся ADR, `C-NN`, новые страницы вики и пункты бэклога — иначе вики распухает от записей, которые никто не перечитывает, и через полгода врёт в деталях.

Расхождение документа с кодом — `update_existing` независимо от того, в этой ли задаче оно возникло: чтение вики перед задачей и есть механизм, которым расхождения ловятся. Прав при этом не всегда документ: неверен код — состояние `none`, чинится код.

## Идеология

Протокол агента (`CLAUDE.md`) стоит на принципах «думать до кода · минимум кода · хирургические правки · проверяемые критерии · корректность до оптимизации · зелёные тесты не приёмка», а wiki замыкает цикл: агент знает, **что именно** читать перед задачей и **что именно** делать с документацией после — включая законный ответ «ничего». Нумерация и форматы записей — в шапках самих файлов; сквозные принципы документирования — в `RULES.md §Принципы документирования`.

Проверено в бою на нескольких проектах; изменения приезжают обратно инкрементом из живой вики (`/agent-wiki:upstream`), а не придумываются в шаблоне.
