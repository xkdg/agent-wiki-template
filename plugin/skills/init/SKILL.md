# Развернуть кит в проекте

Процедура целиком — `kit/INSTALL.md §init` в репозитории кита; здесь — как её запустить. Ничего не коммитить без согласия владельца.

## 1. Проверить проект

- Корень проекта — текущий рабочий каталог, если владелец не назвал другой.
- Есть `wiki/.kit-version` → кит уже стоит: предложить `/agent-wiki:sync` и остановиться.
- Есть `CLAUDE.md` или `wiki/` без `wiki/.kit-version` → это миграция: сказать владельцу, что существующее не будет перезаписано, и спросить, мигрировать ли. Согласен — после шага 2 вести по `$KIT/kit/INSTALL.md §Миграция` целиком, а не по шагам 3–5 ниже: одного `init` мало, без переноса `CLAUDE.md` и правки `INDEX` проект останется на старом протоколе с отметкой новой версии.

## 2. Получить кит

Каталог кита — `${CLAUDE_PLUGIN_DATA}/kit`; если переменная не подставилась — временный каталог. Нужен полный клон.

```bash
KIT="${CLAUDE_PLUGIN_DATA}/kit"
if [ -d "$KIT/.git" ]; then git -C "$KIT" fetch -q origin && git -C "$KIT" checkout -q --detach origin/main; else git clone -q https://github.com/xkdg/agent-wiki-template "$KIT"; fi
```

## 3. Развернуть

```bash
python "$KIT/kit/kit.py" init --project "<корень проекта>"
```

Нет `python` — `python3`. Скрипт печатает, что создано и что уже было.

## 4. Заполнить заготовки — с владельцем

По `kit/INSTALL.md §init` п. 4. Коротко: черновик `INDEX §Проект` и `§Карта кода` по коду и README — показать владельцу; инварианты `QUICK_REF §Границы` называет владелец, из кода — только кандидаты. Пустой проект — оставить подсказки как есть.

## 5. Отчёт

Что создано, что осталось заполнить, версия кита из `wiki/.kit-version`. Напомнить: `CLAUDE.md` с импортами вики подхватится в следующей сессии или после `/clear`.
