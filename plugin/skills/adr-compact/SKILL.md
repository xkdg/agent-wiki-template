# Компакция ADR в реестр

Решение владельца: подробных ADR больше 10 — сворачиваются **все, кроме `proposed`**. Свёрнутая запись не правится, кроме статуса: новый ADR, который её заменяет, сразу меняет статус в её заголовке и дописывает строку «Заменено ADR-NNNN: <что>».

## Перед стартом прочитать

- `wiki/adr/` целиком и `REGISTRY.md`, если уже есть; `RULES.md §Принципы документирования` (нумерация, амортизация).
- Порог и что считать подробным — `RULES.md §После задачи`.

## Критерии приёмки владельца (2026-10-13)

- В `wiki/adr/` — только `_TEMPLATE.md`, `REGISTRY.md` и `proposed`.
- Действующая запись — 2–4 предложения: решение; главное отвергнутое с причиной; цена или ключевое последствие. Без отвергнутого агенты снова предлагают отброшенное — ради него ADR и пишутся.
- Отменённая — 1–2 предложения: что было и чем заменено. Частично отменённая — действующая часть по правилу выше плюс фраза «Заменено ADR-NNNN: <что>».
- `git show <коммит>:<путь>` из каждой записи печатает полный текст, совпадающий с удалённым файлом.
- Ссылок вида `adr/00NN` в репозитории нет, кроме строк `git show` в реестре; каждый упомянутый `ADR-00NN` — заголовок реестра или подробный файл.
- В коде изменились только комментарии.

## Последовательность

1. **Инвентарь.** Подробные файлы и их `Status`; `proposed` — не трогать. Повторная компакция: для каждого `Supersedes` сворачиваемых ADR проверить, что статус и строка «Заменено» в целевой записи реестра уже стоят, — иначе дописать. Для каждого — последний коммит, менявший файл: `git log -1 --format=%h --abbrev=12 -- <путь>` — указатель живёт вечно, короткий хеш со временем станет неоднозначным; сверить `git show <коммит>:<путь>` с текущим файлом (рабочее дерево должно быть закоммичено).
2. **Ссылки до сворачивания.** Все упоминания номеров по рабочему дереву, а не `git ls-files` — ссылки живут и в игнорируемых файлах (`.env`): `grep -rnE '(wiki/)?adr/0[0-9]{3}|\b0[0-9]{3}-[a-z0-9-]+\.md|ADR[ -]?0[0-9]{3}'` без `.git`, виртуальных окружений, сборок. Отдельно — ссылки на секции (`§…` после номера) и утверждения, которые цитируют ADR ради конкретного факта (исключение из инварианта, поле, дата поправки), а не ради решения: этот факт обязан остаться в записи или уже жить в коде.
3. **Образцы.** Шапка реестра и две записи — действующая и (если есть) частично отменённая — показать владельцу до остальных.
4. **Реестр.** Записи по номеру, формат ниже; ссылка на полный текст — коммит из шага 1. Запись длиннее лимита допустима, если на неё ссылаются ради нескольких фактов, — назвать в отчёте.
5. **Замена ссылок** — скриптом по списку файлов из шага 2, **исключив `REGISTRY.md`**: `(wiki/)?adr/(0NNN)(-<slug>.md)?` и относительные `0NNN-<slug>.md` между ADR → `ADR-NNNN`; `ADR-NNNN §Секция` → номер без секции.
6. **Удаление** подробных файлов; `INDEX.md` — строка роутинга ADR и абзац под таблицей «Куда идти» (форма — `template/wiki/INDEX.md`, шаблон кита (`${CLAUDE_PLUGIN_DATA}/kit/`; нет — клон по `source` из `wiki/.kit-version`)).
7. **Проверка:** критерии выше; линтер проекта по изменённому коду; `doc-auditor` с фокусом на ADR — каждая ссылка находит опору в записи, смысл записей сверен с полным текстом. Найденное — дописать в записи, не в код.
8. Diff владельцу, коммит по одобрению.

## Формат реестра

```markdown
# Реестр архитектурных решений

> Свёрнутые ADR: решение, главное отвергнутое, цена; полный текст — в git по ссылке
> в записи. Новый ADR пишется подробным файлом `00NN-<тема>.md` по `_TEMPLATE.md`;
> когда подробных (без `proposed`) больше 10 — все сворачиваются сюда.
> Номер `ADR-00NN` вечный и не переиспользуется; следующий — `INDEX.md`.

## ADR-00NN · YYYY-MM-DD · accepted — <тема>

<решение>. Отвергнуто: <вариант> (<причина>). Цена: <что платим>.
Полный текст: `git show <коммит>:wiki/adr/00NN-<slug>.md`

## ADR-00NN · YYYY-MM-DD · accepted, частично заменён ADR-00MM — <тема>
…действующая часть… Заменено ADR-00MM: <что>.
```

Повторная компакция дописывает записи в конец существующего реестра.

## Ловушки

- **Ссылки на секции** (`ADR-0007 §Последствия`) — после сворачивания секций нет. Пилот FlatMatch: 9 таких ссылок в коде, тестах и миграциях.
- **Ссылки ради детали, а не решения** (`QUICK_REF`, `APP_STORE`, комментарии кода): без шага 2 они молча теряют опору. Пилот: `doc-auditor` нашёл 6 таких мест уже после сворачивания.
- **Замена задевает сам реестр:** строки `git show …:wiki/adr/00NN-….md` превращаются в `ADR-NNNN`. Пилот: пришлось восстанавливать все 9 указателей.
- **macOS:** `grep -Z` в BSD — распаковка, а не нулевой разделитель; zsh не делит переменную по строкам. Список файлов — через файл и скрипт. Пилот: два прогона замены прошли вхолостую.

## Что писать в отчёт

Сколько свёрнуто и сколько оставлено `proposed`; сколько ссылок переписано и где (вики / код / вне git); находки `doc-auditor` и как закрыты; записи сверх лимита и почему; коммит.
