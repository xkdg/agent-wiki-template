# Улучшение из проекта — в кит

Процедура целиком — `kit/INSTALL.md §upstream`. Кит растёт из живых проектов: без прецедента в проекте изменение не предлагается.

## 1. Сформулировать и согласовать

- Что меняется, в каком файле кита (`template/...` — файлы проекта; `plugin/agents/...`, `plugin/skills/...` — роли и скиллы), почему, на каком прецеденте.
- Что в изменении проектное и в кит не идёт — отделить.
- Показать владельцу формулировку и дождаться «да». Без одобрения — только `propose_new` в финале.

## 2. Внести в кит

```bash
KIT="${CLAUDE_PLUGIN_DATA}/kit"
if [ -d "$KIT/.git" ]; then git -C "$KIT" fetch -q origin && git -C "$KIT" checkout -q --detach origin/main; else git clone -q https://github.com/xkdg/agent-wiki-template "$KIT"; fi
git -C "$KIT" checkout -b "upstream/<короткое-имя>"
```

- Правка — в стиле файла, хирургически.
- `CHANGELOG.md`: дата, что изменилось, прецедент; изменение структуры — с инструкцией миграции проектов.
- `kit/VERSION`: patch — формулировки; minor — новое правило, роль или скилл; major — изменение структуры с миграцией.
- Изменили роли, скиллы или манифесты — `claude plugin validate "$KIT"`, если CLI есть.

## 3. Отдать

- Коммит; push ветки; PR через `gh pr create`, если есть права. Нет прав — показать владельцу diff (`git -C "$KIT" diff origin/main`) и команды.
- В `main` напрямую — только по явному слову владельца.

## 4. Вернуть в проект

После слияния: роли и скиллы обновятся сами (плагин версионируется по коммиту). Файлы проекта — `/agent-wiki:sync`: конфликт по этому файлу уйдёт, потому что в ките теперь та же правка.
