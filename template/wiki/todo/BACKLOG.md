# Бэклог

Список **намерений**: что планируем сделать и по какому признаку это будет сделано. Состояние системы — `context/QUICK_REF.md` (факты, пороги, формулы) и ADR; отдельного реестра долгов нет. Что уже сделано — git log и ADR, здесь этого нет.

**Пункт заводится по одобрению владельца продукта** — попутную находку агент называет в финале ответа, а не вписывает сюда молча. Находка, которую можно починить на месте, чинится на месте: бэклог не реестр долгов (`RULES.md §Принципы документирования`). Закрытое направление отсюда амортизируется — доведённое живёт в ADR и git log, а не строкой «сделано» здесь.

**Единица работы** — *назвать свою: блок продукта, стадия пайплайна, сервис. Единица выбрана так, чтобы у пункта был проверяемый признак завершённости, а не «улучшить X».*
