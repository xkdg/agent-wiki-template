## Проект

*2–4 предложения: что делает система, для кого, что на входе и что на выходе; одной строкой — пайплайн или структура. Фактическое описание без маркетинга. Дальше — ключевые архитектурные развилки со ссылками на ADR: то, чего агент не выведет из кода за разумное время.*

*Здесь же — где искать недоделанное и где искать сделанное, чтобы вторая копия статуса не заводилась: планы — `todo/BACKLOG.md`, сделанное — ADR и git log.*

Списанный ADR удаляется вместе со своим номером: номер не переиспользуется, история живёт в git log. Следующий номер — `0001`, форма — `adr/_TEMPLATE.md`.

## Карта кода — роль читается из пути

*Опционально, но окупается быстро: дерево пакета с однострочным назначением каждой директории. Ценность не в списке файлов — его даёт файловая система, — а в том, что из пути читается роль модуля и направление зависимостей.*

```
<пакет>/
├── <точки входа>       ← пути команд неизменны
├── core/               ← основание: конфиг, БД, события — не знает ни о ком
├── <sources|adapters>/ ← внешние данные
└── <domain>/           ← прикладная логика
```

*Если направление импортов важно — проверять его тестом, а не обещанием (обход AST по всему пакету), и назвать этот тест здесь. Тогда модуль, положенный в корень «пока непонятно куда», роняет тест, а не остаётся жить.*

*Ниже — отображение понятий на файлы, чего файловая система не даёт, и потому поддерживается руками. Новый документ таблицу не меняет: строка правится, только когда появилась подсистема или сменился канонический источник по строке.*

| Подсистема | Куда идти |
|---|---|
| *например, скоринг* | *`adr/0007-….md`, `QUICK_REF §Формулы`, `<путь к коду>`* |
| *например, анти-бан* | *`C-12`, `<путь к коду>`* |

## Области ADR

Условия, при которых предлагается ADR, — `RULES.md §Когда предлагать ADR`. Здесь — по каким признакам задетая область узнаётся в этом проекте. *Левая колонка переносится как есть, правая заполняется под проект: неприменимую область пометить `—`, свою — дописать.*

| Область | Признаки в этом проекте |
|---|---|
| **State machine** | *финальные статусы, флаги и переходы; где они заданы* |
| **Схема БД** | *механизм миграций, ключевые таблицы* |
| **Контракт API / CLI** | *модули точек входа, где описаны флаги и эндпоинты* |
| **Протокол между компонентами** | *типы и события, которыми компоненты обмениваются* |
| **Конфиги / пороги / формулы** | *где живут пороги: таймауты, TTL, размеры батчей* |
| **Инвариант из `QUICK_REF §Границы`** | *сколько пунктов; менять — сначала ADR* |
| **Cross-cutting** | *обработка ошибок, retry, деградация, наблюдаемость* |
| **Стоимость** | *если есть оплачиваемые внешние вызовы — их лимиты и цены* |

| Что произошло | Действие |

| *Изменён артефакт, приёмка которого требует прогона (промпт, модель, эвал-набор)* | *в вики — `none`, но без прогона не принимается; версии уезжают в трейс* |
