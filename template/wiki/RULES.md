# Правила документации

> **Ядро agent-wiki-template.** Файл одинаков во всех проектах и обновляется `/agent-wiki:sync` —
> проектное сюда не писать. Проектная часть тех же правил — в `INDEX.md`: таблица областей ADR и
> проектные маршруты «после задачи». Улучшение, нужное всем проектам, — предложение в кит
> (`CLAUDE.md §Протокол агента`), а не правка на месте.

Читается перед каждой задачей вместе с `INDEX.md` и `context/QUICK_REF.md`. Здесь: когда предлагать
ADR и скилл, что делать с документацией после задачи, принципы документирования.

---

## Когда предлагать ADR

Предложение, а не создание: ADR заводится после явного одобрения (`CLAUDE.md §Протокол агента`).
Объём правки критерием не является — однострочная правка бывает значимой, а рефакторинг на тысячу
строк не бывает.

**Все четыре условия сразу:**
1. принято долговечное решение, а не просто выполнена задача;
2. есть минимум две реалистичные альтернативы, и отвергнутая отсечена названным критерием;
3. решение влияет шире собственной реализации;
4. мотивация неочевидна из кода, тестов и конфигурации.

**И задета хотя бы одна область** — таблица с признаками этого проекта: `INDEX.md §Области ADR`.
Области: state machine · схема БД · контракт API / CLI · протокол между компонентами · конфиги,
пороги, формулы · инвариант из `QUICK_REF §Границы` · cross-cutting · стоимость.

**ADR не заводится** для обычного bug fix, локального рефакторинга, имени файла или функции, поля по
существующему паттерну, реализации уже принятого решения, восстановления прежнего поведения,
настройки библиотеки внутри выбранного стека и решения, целиком читаемого из публичного контракта
и тестов.

---

## Когда предлагать скилл

**Скилл — повторяемый процесс; вики — факты и решения; роль субагента — кто исполняет.** Скилл держит
последовательность шагов и ловушки, из-за которых порядок именно такой. Числа, пороги и state machine
он не дублирует, а ссылается на вики.

Предложение, а не создание — `propose_new`, создаётся по одобрению. **Все условия сразу:**
1. процесс прогнан минимум второй раз — повтор подтверждён фактом, а не прогнозом, — или владелец
   назвал его регулярным;
2. в нём есть порядок, который не выводится из кода за разумное время: шаги зависят друг от друга,
   есть ловушки, необратимые операции или ручная приёмка;
3. процесс не сводится к одному скрипту. Сводится — нужен скрипт, а не скилл: правило, которое
   проверяется машиной, проверяется машиной.

**Форма** — `.claude/skills/<kebab-name>/SKILL.md`:
- `description` — что делает и все формулировки, которыми о процессе просят, с оговоркой «даже если
  слово „скилл“ не звучит»: скилл находится только по нему.
- Секции: «Перед стартом прочитать» — ссылки на вики, не пересказ · «Критерии приёмки владельца» —
  с датой фиксации · «Последовательность» · «Ловушки» — каждая с тем, чего стоила · «Что писать
  в отчёт».
- У процесса есть соседние задачи с похожей лексикой — набор `evals/trigger-eval.json`: половина
  запросов должна вызывать скилл, половина — near-miss, которые не должны.

**Жизненный цикл.** Процесс изменился или на ловушку наступили заново — `update_existing` скилла.
Новый скилл вносится в таблицу скиллов `INDEX.md`. Шаги скилла можно поручать ролям субагентов:
скилл говорит, что делать, роль — кто делает.

Скилл, нужный во всех проектах, а не в этом, — предложение в кит, а не `.claude/skills/` проекта.

## После задачи — `documentation_action`

**Умолчание — `none`.** Ниже общие маршруты «что куда»; проектные — `INDEX.md §Проектные маршруты`.
Чего нет ни там, ни здесь, то по умолчанию `none`. Состояния и различие «неверное чинится, новое
называется» — `CLAUDE.md §Протокол агента`.

| Что произошло | Действие |
|---|---|
| Изменено число, статус, формула или контракт, описанные в `QUICK_REF` | `update_existing`: `context/QUICK_REF.md` |
| Изменён процесс, интеграция или схема данных, описанные в `PRODUCT` | `update_existing`: `context/PRODUCT.md` — секция и её диаграмма |
| Изменён контракт команды или эндпоинта из `README` | `update_existing`: `README.md` |
| Появилась подсистема или сменился канонический источник по строке | `update_existing`: таблица подсистем в `INDEX.md` |
| Изменён инвариант из `QUICK_REF §Границы` | **оба сразу:** `update_existing` `QUICK_REF` — иначе документ, читаемый перед каждой задачей, остаётся с ложным инвариантом; и `propose_new`: ADR со строкой `Supersedes` |
| Прошёл gate `§Когда предлагать ADR` | `propose_new`: ADR |
| Приём или дефект встретился в двух независимых местах либо однажды дорого | `propose_new`: `C-NN` — при остальных условиях шапки `CONVENTIONS.md`: шире одного файла, названное последствие, не держится тестом или типом |
| Прошёл gate `§Когда предлагать скилл` | `propose_new`: скилл |
| Изменился процесс, описанный в скилле, или на его ловушку наступили заново | `update_existing`: `.claude/skills/<name>/SKILL.md` |
| Улучшение протокола, шаблонов, ролей или общих скиллов, нужное всем проектам | `propose_new`: изменение кита; после одобрения — `/agent-wiki:upstream`. Файлы ядра в проекте не править |
| Сознательный костыль остаётся жить | назвать в финале; **границу, которую он держит, — `update_existing`: `QUICK_REF`** |
| Попутная находка, идея или отложенная проблема | назвать в финале. `BACKLOG` и вики не трогать |
| Задача велась по ТЗ | `[x]` и статус в самом файле; `done` + подтверждённая приёмка → амортизация и удаление |

Расхождение, замеченное при чтении, — тоже `update_existing`, независимо от того, чем оно вызвано:
документ, который врёт, дороже документа, которого нет.

## Принципы документирования

- **Амортизация.** Документ живёт, пока его содержимое не переехало в долговечное место. Переехало — исходный удаляется: две копии расходятся, и вторая начинает врать.
- **Единственный источник истины.** Каждый факт живёт в одном месте; смежный документ на него ссылается, а не пересказывает.
- **Ссылки — по необходимости.** Ссылка ставится в тексте там, где без неё теряется контекст. Отдельной секции связей и обратных ссылок нет: граф, поддерживаемый руками, устаревает первым, а отсутствие ссылки дефектом документа не является.
- **Правило, которое можно проверить машиной, проверяется машиной.** Тест, тип, схема или линтер вместо записи в вики; текстовое правило — когда автоматизировать нечем. Запись тогда ссылается на механизм, а не пересказывает его.
- **Реестра долгов нет.** Найденная проблема либо чинится на месте, либо называется в финале; пункт `todo/BACKLOG.md` заводится по одобрению. Отдельного списка «с чем живём» не бывает — архив, который никто не разгребает, начинает врать. Принятый компромисс описывается в «Последствиях» того ADR, который его породил, вместе с ценой.
- **Нумерация.** `ADR-00NN` и `C-NN` — sequential, **никогда не переиспользуются**.
- **Ссылки на смертное.** ТЗ-файлы умирают — из ADR, `CONVENTIONS`, `PRODUCT` и `QUICK_REF` на них не ссылаться. Исключение — помеченные постоянными.
