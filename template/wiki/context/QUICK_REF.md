# Quick Reference — оперативные факты

> Читается на каждой задаче (вместе с `wiki/INDEX.md` и `wiki/RULES.md`). Здесь то, что должно быть в голове агента
> постоянно. **Тест на попадание:** без этого факта агент либо заново выведет его из кода,
> потратив контекст, либо молча нарушит.
>
> Здесь «что», а не «почему»: обоснование решения → ADR, правила реализации с прецедентами →
> `CONVENTIONS.md` (`C-NN`), процессы схемами → `PRODUCT.md`, история замеров и прежние
> редакции → git log, ADR и замеры. Изменил число, статус или границу в коде → обнови здесь же
> (`RULES.md §После задачи`).
>
> **Шаблон.** Обязательна только секция `§Границы` — остальную структуру проект выращивает сам.
> Типовые категории содержимого:
> - домен: константы, пороги, формулы, whitelist'ы — «значение · где в коде · какой ADR»;
> - state machine / режимы: статусы, флаги, шаги, FSM — единственный источник правды;
> - контракты данных: state-объекты, канонические форматы (*«страна — ISO alpha-2 uppercase»*);
> - сценарии / стадии: «команда → источники → fallback при сбое», команды запуска;
> - рабочие договорённости проекта: прод-доступ, что агент делает сам, а что — только с
>   подтверждением владельца. `CLAUDE.md` — ядро кита и проектного не держит.
>
> Пустые секции удалять, «TBD» не оставлять.

## Границы (нарушение = сначала ADR)

*Единственный дом системных запретов: архитектурные инварианты + операционные перечни к ним
(что не передаётся во внешний вызов, что запрещено в логах, …). Пункт формулируется так, чтобы
из него было видно, чем он держится: тестом, типом, топологией кода — или только этой строкой.
Изменение пункта отсюда — повод предложить ADR (`RULES.md §Когда предлагать ADR`).*

1. *Сервисы не импортируют друг друга — только общую библиотеку*
2. *PII не покидает процесс: в LLM и логи не попадают `<id>`, дата рождения, координаты*
3. *Миграции БД — только через централизованный механизм, не из кода сервисов*
